## 0. 本规格与现有文档的关系（必须先读）

本次方向是用户拍板的**定向风格例外**：项目整体美术圣经（`art-bible.md`）仍是卡通 Stylized，**仅这 8 只成年动物**切换为写实偏精致。因此：

1. 本规格是这 8 只动物的**唯一视觉权威**；其余资产（建筑/植物/道具/Quaternius 动物/升级链）继续遵守卡通圣经。
2. 与现有文档存在 **3 处硬冲突**（详见 §5.1），需主理人确认是否同步修订 `art-bible.md` / `asset-specs.md`，否则 QA 脚本（M1「材质必须 toon / 无写实 PBR 残留」）会把新资产判为不合格。
3. 本规格不修改任何源文件、不动 `manifest.json`；只产出「规格 + 生成 prompt + 验收标准」，3D 生成与清洗由 engineering-lead 执行。

## 1. 写实偏精致的操作性定义

### 1.1 风格光谱定位

```
纯卡通 toon ──────────────── 风格化写实（本目标） ──────────────── 照片级写实
  ▲ 现仓库                      ★ 落点                           △ 不做
Q 版/平面色块              真实解剖比例 + 真实物种色        次表面散射/根根毛发/
                                                   4K 扫描贴图
```

- **落点定义**：解剖比例与体态**贴近真实物种**（不再 Q 版大头短腿）；配色取**真实物种色相**但整体**提亮 + 饱和度略高于照片**（保证 5 米可读性，与明亮农场环境衔接）；材质走 PBR。
- **明确不做**：照片级写实（Substance 扫描级）、恐怖谷、血腥、阴暗打光。
- **可读性原则（继承圣经）**：即便写实，动物剪影仍要在 5 米外一眼认出「鸡/牛/羊/猪/鸭/鹅」。

### 1.2 渲染与材质（技术美术）

| 项 | 决定 | 说明 |
| --- | --- | --- |
| 材质类型 | `MeshStandardMaterial`（PBR） | 8 只动物全部切 standard；**不再用 MeshToonMaterial / gradientMap**。这是对卡通圣经 §5.1 的例外 |
| 贴图通道 | baseColor + normal + ORM（roughness/metallic/AO 打包单张） | metallic 全 0（无金属部件）；roughness 分区（羽毛/毛 0.85–1.0，喙/角/蹄 0.4–0.6，眼 0.05） |
| 环境反射 | 需要**低强度 IBL / envMap**（建议强度 0.3–0.5） | 写实材质没有环境反射会「死黑死灰」；需与程基岩确认管线是否注入 envMap（见 §7 风险） |
| 色调映射 | 沿用 `ACESFilmicToneMapping` + `SRGBColorSpace` | 与现有管线一致，不用改 |
| 轮廓 | **取消动物轮廓（Outline）** | 卡通圣经 §4 要求动物描边；写实动物 + 硬描边会像「赛璐璐贴片」，本 8 只豁免 |
| 光源 | 沿用现场景主光 + 半球光，新增**边缘光/rim（可选，强度 0.2）** | rim 帮助写实动物从亮色卡通背景中脱离（调和手段，见 §5.2） |
| 阴影 | 沿用主光 1024 阴影；动物 castShadow | 不新增多光源投影（移动端预算） |

### 1.3 毛发策略（三级，控成本核心）

| 级别 | 适用 | 做法 |
| --- | --- | --- |
| **Lv1 纯 PBR 质感** | 鸡（羽）、鸭（羽）、鹅（羽）、猪（短毛） | 不建毛束；靠 **baseColor 羽纹 + normal 微鳞/羽片凹凸 + roughness 分区** 模拟。鸡背/翼用 normal 做羽片层叠 |
| **Lv2 短毛 PBR** | 牛（棕牛/荷斯坦） | 牛毛很短：normal 做 2–4mm 短毛刷感 + roughness 微噪；不做独立毛束 |
| **Lv3 毛簇网格** | 羊（羊毛） | **必须做毛簇**：剪毛前 = 羊身覆盖 30–60 个卷曲毛簇（sculpted clumps，可用 2–3 层 card/几何片替代，禁止 strand 毛发）；**剪毛后 = 贴身短毛变体**（配合玩法 ITM-011 羊毛，见 design/asset-manifest.md）。毛簇不做物理模拟，用静态绑定 + 轻微顶点摆动（可选） |

> 铁律：**不做 strand/粒子级真实毛发**（Web 性能不可行），也**不做纯色无质感**（会退回卡通）。羊是唯一需要额外几何的动物。

### 1.4 面数预算（LOD0，单只）

| 物种 | LOD0 | LOD1（≈50%） | LOD2（≈25%） | 对照（现卡通规格） |
| --- | --- | --- | --- | --- |
| 鸡 / 鸭 | **8k**（6–10k） | 4k | 2k | 1.5k |
| 鹅 / 猪 / 羊 | **12k**（10–14k） | 6k | 3k | 羊/猪 2.5k |
| 牛 | **16k**（14–18k） | 8k | 4k | 3.5–4k |

- 写实需要比卡通高约 3–4 倍面数。**同屏风险**：若 8 只全部 LOD0 同屏 ≈ 80–100k tris，占全场景 300k 预算的 1/3，可接受但**必须启用 LOD**（LOD 切换距离沿用 pipeline §2.4 / 建议 0 / 18 / 40 米）。
- 允许三角形网格（写实模型几乎必然三角化）；要求无 N-gon、无重叠面、无 z-fighting。

### 1.5 纹理分辨率与通道

| 物种 | baseColor | normal | ORM | 说明 |
| --- | --- | --- | --- | --- |
| 鸡 / 鸭 / 鹅 | 1024×1024 | 1024×1024 | 512×512 | 羽纹细节需要 1024 |
| 猪 / 羊 | 1024×1024 | 1024×1024 | 512×512 | 羊毛色块、猪肤色渐变 |
| 牛 | **2048×2048** | 1024×1024 | 512×512 | 荷斯坦黑白斑需高分辨率避免糊边 |

- 全部 2 的幂；源 `.png`，运行期 **KTX2/Basis**（沿用 pipeline §4）。
- 单只 VRAM 估算：牛 ≈ (2048² + 1024² + 512²) × ~1MB/1024² ≈ 5.2 MB；其余 ≈ 2.3 MB。8 只全载 ≈ **≤ 26 MB**（在 128 MB 预算内，但会挤占其它资产，需工程侧确认同屏动物数）。

### 1.6 色彩基调（写实物种色，但向农场环境靠拢）

- 整体色温偏暖、亮度高于真实照片约 10–15%、饱和度略高于真实（约 +5–10%）——这是「偏精致」而非「灰写实」的关键。
- 每物种色板见 §2 逐只表格（HEX 为参考，允许 ±10% 明度抖动，禁止无约束 RGB）。
- 白色/浅色羽（白鸡/白鸭/鹅）**禁止纯白** `#FFFFFF`，用暖白 `#F0EDE4` 系，避免过曝。

### 1.7 GLB 硬性规范（沿用 pipeline §1.1，违反即打回）

| 项 | 标准 |
| --- | --- |
| 单位 | **1 单位 = 1 米**（与 Rapier 一致，禁止场景内 scale 修正） |
| 轴向 | **Y 轴向上** |
| 前向 | **+Z 朝前**：四足 = 鼻尖方向；两足禽类 = 喙尖方向 |
| 锚点 | **脚底中心 = 原点 (0,0,0)**；四足 = 四脚掌着地平面中心；禽类 = 双足着地中心 |
| 姿态 | 默认**中性站姿**（四足四脚平踏、头抬自然高度；禽类直立、尾羽自然上翘）——不做 T-pose（动物无 T-pose 惯例） |
| 禁止 | GLB 内嵌灯光/相机节点；超大未压缩纹理；非 1 米比例 |
| 动画 | 见 §2 每只动画字段；骨骼动画由工程侧处理（AI 生成通常无骨骼，见 §7） |

## 3. 命名规范（新文件命名）

### 3.1 原则：**文件名与 assetId 命名空间保持一致，正式替换时「同名覆盖」**

`manifest.json` 的 `path` 直接引用现有文件名，运行时懒加载按 `assetId` 查表。**同名覆盖 = 零代码改动、零 manifest 改动**，是最稳妥的替换方式。

### 3.2 样本阶段（未验收前，禁止覆盖正式资产）

```
assets/animals/staging/animal_chicken_brown_r.glb     ← 样本鸡（r = realistic）
assets/animals/staging/animal_chicken_brown_r_*.png   ← 样本贴图（若单独导出）
```

- 样本放 `staging/` 子目录，**不写进 manifest**，由工程主理在 `preview.html` 或临时 HTML 里手动加载对比。

## 5. 风格冲突评估（写实动物 vs 卡通环境）

### 5.1 冲突点清单

| # | 冲突点 | 具体表现 | 严重度 |
| --- | --- | --- | --- |
| C1 | **材质体系冲突** | 环境/建筑/植物全走 toon（MeshToonMaterial + 顶点色）；写实动物走 PBR。同屏会出现「平面色块 + 立体 PBR」并置，动物像被 PS 贴图进卡通画 | 高 |
| C2 | **调色板冲突** | 卡通圣经色板是高饱和暖色（牧场绿 `#6BAF4E`、天空蓝 `#7EC8E3`）；真实动物色偏灰调、明度低。写实动物在亮色背景里会显「脏/旧」 | 高 |
| C3 | **光照/反射冲突** | 卡通用 3 阶 gradientMap 明暗；PBR 需要 envMap/IBL 才有材质质感。当前场景若无 envMap，写实动物喙/眼/羽毛会死黑无光 | 中高 |
| C4 | **轮廓规则冲突** | 卡通圣经 §4 规定动物必须描边（inverted hull）；写实动物描边会像赛璐璐贴片，破坏写实质感（§1.2 已豁免，但等于破了一条圣经铁律） | 中 |
| C5 | **面数/纹理预算冲突** | 写实动物面数是卡通 3–4 倍 + 引入贴图（VRAM +26 MB）；与「程序化无贴图省内存」的现有设计相悖 | 中 |
| C6 | **同类资产混搭** | 仓库还有 Quaternius 卡通农场动物（`quaternius_farm_animals_glb/` 的 Cow/Pig/Sheep、`quaternius_animated/` 12 个动画版）——玩家视野里会出现「卡通牛 + 写实牛」 | 中高 |
| C7 | **生命周期一致性** | 本次只换成年（adult），幼崽（chicken_baby/duck_baby/goose_baby/calf/lamb/piglet）仍是卡通——「写实父母 + 卡通幼崽」会在同一生命周期 UI 里同屏 | 中高 |
| C8 | **文档级冲突** | `asset-specs.md` QA 清单「材质为卡通（toon/vertex_color），无写实 PBR 残留」会把新资产直接判不合格；`asset-pipeline.md` M1 同。不修订文档 → 管线自相矛盾 | 高（流程） |

### 5.2 三个调和方案

#### 方案 A · 全部统一写实（环境 + 动物 + 植被全换）

| 维度 | 评估 |
| --- | --- |
| 优点 | 视觉彻底统一、档次最高、无风格撕裂 |
| 缺点 | 范围爆炸：需重建 ~90+ 资产（建筑/升级链/植物/树/道具/Quaternius 全系）；写实 PBR 对 Web/移动端性能压力大；丢失卡通「5 米可读性」；周期从「8 只」变「整库」，用户验收节奏完全改变 |
| 工作量 | 高（≈ 现计划 10 倍以上；多模态生成 + 清洗 + 重做环境光照/材质） |
| 适用 | 仅当用户明确「整库写实重做」且接受长周期 |

#### 方案 B · 动物写实 + 环境卡通保留（当前决策的直接落地 + 桥接手段）

| 维度 | 评估 |
| --- | --- |
| 优点 | 范围锁定 8 只，符合用户当前决策；农场「主角」动物质感提升最明显 |
| 缺点 | 需接受 C1/C2/C3/C6/C7 的残留撕裂，靠桥接手段缓解但**无法完全消除**；C7 幼崽不一致最扎眼 |
| 桥接手段（必须做） | ① 场景加低强度 envMap/IBL（强度 0.3–0.5）让 PBR 动物有质感；② 动物调色向卡通色板靠拢（提亮 +10–15%）；③ 主光 + 0.2 rim 光分离前景；④ ACES 色调映射统一；⑤ 幼崽后续批次跟进（把 7 只幼崽列为 P1.5 补丁，见下） |
| 工作量 | 低-中（8 只生成 + 清洗 + 场景光照小改；幼崽跟进另计） |
| 适用 | 用户坚持「先换动物」且接受阶段式演进 |

#### 方案 C · 折中风格（半写实 / polished stylized）

| 维度 | 评估 |
| --- | --- |
| 优点 | 写实比例 + 解剖，但保留高饱和暖色、轻微夸张特征（更大的冠/更圆身）、PBR-lite（Standard + 低细节贴图）；与卡通环境冲突最小；面数/贴图预算可比方案 B 更省 |
| 缺点 | **不是「真写实」**——如果用户要的是照片级，此方案会被认为「不够写实」；仍需给 8 只 + 幼崽做批次 |
| 工作量 | 低（介于现 toon 与写实之间，生成成功率更高） |
| 适用 | 用户对「写实」的接受度是「精致、不卡通」即可，而非「真实到像照片」 |

### 5.3 推荐方案与理由

**推荐：方案 B（动物写实 + 环境保留 + 桥接）为主，采样阶段用「写实度档位」探用户底线。**

理由：
1. 用户已拍板「写实偏精致」+「全部多模态生成」+「先 8 只」——方案 B 是这三个决策的交集，范围可控、不推翻已确认决策。
2. 方案 A 范围是 B 的 10 倍，违背「先样本验收」节奏；方案 C 需要用户先收回「写实」承诺，也不应默认。
3. **关键补充**：建议把「幼崽 7 只」（lifecycle_*_baby + calf/lamb/piglet）列为**下一批（P1.5）必做**，否则 C7 生命周期不一致会长期暴露；同时同步修订 art-bible/asset-specs 的 QA 条款（C8），否则管线会自动打回新资产。

> 若用户对样本鸡的反馈是「还是不够真」→ 升档到写实度 1.0（见 §6.4 V3）；若反馈是「太写实了不搭」→ 降档到折中（方案 C 光谱）。**样本鸡的意义就是校准这个档位。**

## 6. 成年鸡样本 · 多模态生成 Prompt

### 6.1 生成策略（engineering-lead 执行）

- 用「3D模型与视频特效」技能的文生 3D（或图生 3D）能力；**本规格只给 prompt，不代生成**。

## 7. 风险声明（用户决策颗粒度风险 — 请主理人知悉）

### 7.1 「全部多模态生成」的风险（中-高）

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 精度不可控 | 文生 3D 对「精确 1 米单位 / Y-up / 锚点 / 面数预算 / 贴图通道」无法保证，几乎必然需要工程二次清洗（重拓扑/减面/重命名/贴图烘焙） | 把清洗列入流程（§6.6），不要期望「生成即入库」 |
| 骨骼动画缺失 | 当前多模态 3D 生成**基本不产出可用的骨骼动画**；而 8 只动物的 manifest 大多声明 idle/walk/eat/peck | 若用户要求动画，需工程侧「AI 生成静态 + 手动重定向/重绑骨骼」；若接受静态先验收，动画列 P1.5 |
| 一致性漂移 | 每只动物独立生成 → 8 只之间比例/质感/色温可能不统一 | 每只生成时夹带「风格锚定词」（统一用 V1 的 style keywords + 色板），生成后按 §2 表格校色 |
| 出图即错 | 文生可能出「6 腿鸡 / 错趾 / 斑块糊」等低级错误 | 生成后先人工目检 §4.3，低级错误直接重生成，不浪费时间清洗 |

### 7.2 「写实偏精致」颗粒度的风险（中）

- 文生 3D 的**舒适区是「风格化/半写实」**，要做到「真 PBR 写实 + 干净拓扑」成功率低、反复多。
- 因此样本鸡**不要一上来就赌全写实**：用 V1（主推）+ V3a/V3b（两极）一次出 2–3 只，让用户校准「偏精致」到底偏哪边。
- **明确给主理人的回调信号**：若用户验收样本后仍想要「照片级写实 + 骨骼动画 + 严格面数」，则「全部多模态生成」这一决策在写实颗粒度上**有风险**，需要回调为「多模态生成高模 → 工程重拓扑/减面 → 手动重绑定动画（或混合 CC0 高质量模型）」的混合管线，周期相应 +2–3 天/只。

### 7.3 时间预估：成年鸡样本 → 用户验收循环

| 环节 | 预估 |
| --- | --- |
| 生成 2–3 个变体（文生 3D） | 30–60 分钟（含失败重试） |
| 工程清洗 1 只（单位/锚点/减面/命名/贴图/预览） | 1–2 小时 |
| 场景对比渲染 + 提交用户 | 0.5 小时 |
| 用户验收往返 | 1 次会话（< 1 天） |
| **合计最短（乐观）** | **约 0.5–1 个工作日（纯工作流 2–4 小时 + 1 次用户往返）** |
