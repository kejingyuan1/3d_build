## 1. 视觉锚点与风格参照

**一句话概念**：一个被阳光晒暖的、圆滚滚的童话农场——像翻开一本立体绘本。

**视觉锚点（3 个）**：
1. **圆润**：一切坚硬棱角都要被倒角软化，动物与人物全是 Q 版圆体。
2. **明亮**：高亮度、高饱和、低对比阴影；永远像晴天上午 9 点。
3. **可读**：轮廓清晰、色块分明，隔 5 米仍能一眼认出「这是鸡、这是房子」。

**风格参照板（Moodboard）**：
- 游戏类：《星露谷物语》的建筑配色节奏、《Minecraft》式体素明确性、《Slime Rancher》的饱和高光、《Cozy Grove》的柔和手绘感。
- 艺术类：水彩绘本插画（田园风光）、低模像素风（Low Poly Art）的平面色块。
- **明确不参照**：写实 PBR（Substance 级材质）、阴暗恐怖、赛博霓虹、深色描边漫画风。

**风格统一三原则**（程序化生成与外部资产都必须遵守）：
1. 色板即法律：颜色只能取自第 2 节调色板及派生区间，禁止自由 RGB。
2. 曲率即个性：锐角 < 30° 的棱线必须倒角或圆滑。
3. 面数即层次：面数按第 6 节分级，禁止某个资产「一枝独秀」超预算。

## 2. 配色体系（Color System）

### 2.1 全局调色板（Global Palette）

主色调为**暖绿 + 暖棕 + 天蓝**，整体色温偏暖，饱和度中高、明度偏高。

| 角色 | 名称 | HEX | 用法 |
| --- | --- | --- | --- |
| 主色 01 | 牧场绿 | `#6BAF4E` | 草地、叶冠、藤蔓主色 |
| 主色 02 | 沃土棕 | `#8D6E63` | 土壤、树干、围栏木 |
| 主色 03 | 天空蓝 | `#7EC8E3` | 天空、水体、远景 |
| 辅色 01 | 麦穗黄 | `#F2C14E` | 干草、麦田、阳光高光 |
| 辅色 02 | 奶油白 | `#F5EFE0` | 棚舍墙、羊、牛奶、UI 面板底 |
| 辅色 03 | 石炭灰 | `#9E9E9E` | 石块、道路、屋顶瓦灰 |
| 强调色 01 | 番茄红 | `#E4572E` | 果实、屋顶、交互标记、危险 |
| 强调色 02 | 蓝莓蓝 | `#4A6FA5` | 水桶、机器、选中高亮 |
| 强调色 03 | 鸡蛋黄 | `#FFD166` | 稀有掉落、按钮主色、星星 |
| 深色（轮廓/阴影） | 深墨绿 | `#2F3E2E` | 阴影色、描边色、深色文字 |

### 2.2 配色比例

- **60/30/10 法则**：场景中主色系 60%、辅色系 30%、强调色 10%。
- 强调色只用于「可交互/有反馈」的物件，保证玩法可读性优先。
- 禁止大面积使用纯黑 `#000000` 与纯白 `#FFFFFF`（用奶油白与深墨绿替代）。

### 2.3 随机配色区间（程序化生成专用）

程序化生成资产的颜色**必须从下列区间采样**，禁止越过区间：

- 植物绿：`H(90–140°) S(45–70%) L(45–60%)`
- 土壤棕：`H(20–40°) S(30–50%) L(40–55%)`
- 皮毛色：`H(25–50°) S(35–60%) L(55–75%)`（牛/羊/鸡通用）
- 强调红：`H(5–20°) S(60–80%) L(50–60%)`

### 2.4 功能色（可访问性相关）

- 交互高亮：蓝莓蓝 `#4A6FA5`（与红/绿均区分，色盲友好）。
- 危险/敌对：番茄红 `#E4572E`。
- 成功/丰收：鸡蛋黄 `#FFD166`。
- 上述三色同时用于 UI，具体可访问性分级见 `design/accessibility-requirements.md`。

## 3. 光影风格（Lighting）

**结论：采用「单方向光 + 环境光」实时光照，不烘焙光照贴图（Web 部署、场景程序化生成、动态物体多）。**

### 3.1 光照配置（Three.js 参数建议）

| 灯 | 类型 | 参数建议 |
| --- | --- | --- |
| 主光 | DirectionalLight | 强度 1.0–1.4，位置 (10, 20, 8)，色温偏暖 `#FFF3D6` |
| 环境光 | HemisphereLight | 天空色 `#BFD8F5`、地面色 `#D9C9A3`、强度 0.5–0.7 |
| 补光（可选） | AmbientLight | 强度 0.2 以下，避免死黑 |

- **禁开**：真实阴影中的大面积接触阴影过深。阴影贴图分辨率 1024 足够，方向光 `shadow.camera` 范围收紧到场景包围盒。
- **色调映射**：`THREE.ACESFilmicToneMapping`（建议）或 `NoToneMapping` + 手工压高光；`outputColorSpace = SRGBColorSpace`。
- **雾**：`Fog` 颜色取天空蓝 `#7EC8E3`，近距离 start ≈ 场景半径 0.6 倍，制造绘本景深。

### 3.2 阴影

- 主光源开启 `castShadow`；小型动态物件（动物、道具）开启 `castShadow`。
- 地面/建筑等静态大体量开启 `receiveShadow`。
- 单个光源投影即可，**禁止多光源投影叠加**（移动端性能）。

### 3.3 卡通明暗策略

- 使用 `MeshToonMaterial` 的 `gradientMap`（3 阶色带：亮/中/暗），配合光照产生**硬边卡通明暗**。
- 暗部色 = 基础色 × 0.55–0.65（向深墨绿 `#2F3E2E` 偏移，不用纯黑）。
- 不接受逐像素 smooth 渐变阴影（写实感会破坏风格）。

## 4. 轮廓处理（Outline）

**结论：主角/动物/可交互道具启用轮廓；纯装饰植被/远景可无轮廓。轮廓统一为「背面挤出法」（inverted hull）实现，不在贴图上画描边。**

### 4.1 轮廓实现（技术美术约定）

- 原理：复制网格、法线翻转、沿法线外扩 1.5–3% 网格半径，材质为单色（深墨绿 `#2F3E2E`）、`side: BackSide`。
- 更优做法：用扩展 `OutlinePass` 后处理（统一控制，不增加几何体面数），但**需要与程基岩确认管线支持**后再定，默认走 inverted hull。
- 轮廓宽度：屏幕占比 1.5–3px 等效；随距离可淡出（远景轮廓关闭）。

### 4.2 轮廓启用规则

| 资产类型 | 是否描边 |
| --- | --- |
| 主角/农场主角色 | ✅ 必须 |
| 动物（鸡/牛/羊等） | ✅ 必须 |
| 可交互道具（果实、工具、可拾取物） | ✅ 必须 |
| 建筑主体 | ⚠️ 可选（建议描边，突出可读性） |
| 植被/树木/草地 | ❌ 不描边（用配色区分） |
| 远景（>30m） | ❌ 不描边（性能 + 自然淡出） |

## 5. 材质规范（Material）

### 5.1 卡通材质方案

**推荐：`THREE.MeshToonMaterial` + `gradientMap`（3 阶）为主；`MeshStandardMaterial` 仅用于金属/水体等特殊对象。**

| 属性 | 参数建议 |
| --- | --- |
| 材质类型 | MeshToonMaterial（默认）/ MeshStandardMaterial（金属、水体） |
| gradientMap | 3×1 纹理：亮 `#FFFFFF` → 中 `#C9C9C9` → 暗 `#8A8A8A` |
| roughness（若用 Standard） | 0.7–1.0（哑光为主） |
| metalness（若用 Standard） | 0（非金属）/ 0.6–0.9（仅金属道具） |
| 反射 | 不启用 envMap 反射（或极弱 0.1） |
| 自发光（Emissive） | 仅 UI 信号/丰收特效使用，强度 ≤ 0.5 |

**MatCap 说明**：`MeshMatcapMaterial` 可做纯卡通明暗，但会丢失方向光投影信息、与阴影系统冲突，**默认不用**；如美术需要可作单资产特例，需标注审批。

### 5.2 纹理尺寸规范（同屏预算分级）

以**单屏同屏纹理总预算 ≤ 128 MB（GPU VRAM）**为硬上限，分级如下：

| 分级 | 尺寸 | 适用资产 | 同屏数量上限建议 |
| --- | --- | --- | --- |
| S | 256×256 | 小道具、果实、鱼、小部件 | 同屏 ≤ 40 张 |
| M | 512×512 | 动物、植物、小建筑、围栏 | 同屏 ≤ 30 张 |
| L | 1024×1024 | 主建筑、地形地表、招牌、水面 | 同屏 ≤ 8 张 |
| XL | 2048×2048 | 仅 UI 大图 / 启动画面 | 运行时 ≤ 2 张 |

- **全部纹理必须为 2 的幂**（256/512/1024/2048）。
- 格式：运行期压缩 `WebP` 或 `KTX2`（若管线支持）；源文件 `.png`。
- **程序化生成资产默认无贴图**：用顶点色（vertex colors）+ 纯色材质，这是程序化资产的优势（省纹理内存），风格上完全吻合卡通平面色块。

### 5.3 贴图通道

| 通道 | 是否需要 | 说明 |
| --- | --- | --- |
| albedo（base color） | ✅ 需要 | 必带；卡通平面色，禁止高频噪点纹理 |
| normal | ❌ 默认不需要 | 卡通低模用不着法线细节；仅大块平面（地面）可选 |
| roughness/metalness | ⚠️ 可选 | 仅 Standard 材质使用；可用单通道打包 |
| AO | ⚠️ 可选 | 低模可省；如用需 1 张 256 灰阶 |
| 顶点色 | ✅ 程序化资产必用 | 替代贴图完成色块分布 |

## 6. 造型语言（Form Language）

### 6.1 比例规范（Q 版）

- **人物头身比 1:2.5**（Q 版大头），肩宽 ≈ 头宽的 1.3 倍。
- **动物头身比 1:2.5 ~ 1:3**，头大、四肢短、身体圆。
- **建筑**：矮胖比例，屋檐高度 ≈ 建筑宽度的 0.5–0.6 倍；门高 ≈ 角色身高的 0.8 倍（保证 Q 版角色能进门）。
- 所有资产底座落地线统一在 **Y=0**（见资产规格文档锚点规范）。

### 6.2 圆角/倒角规范

- 所有可见棱边：**倒角半径 ≥ 边长的 2–3%**（程序化生成用 `cylinder`/`capsule` 基本体或 bevel）。
- 立方体类建筑：至少顶边倒角，避免尖锐直角。
- 禁止出现 < 1cm 的微小倒角（浪费面数且看不出效果）。

### 6.3 低模拓扑原则

1. **四边形优先**：尽量 quad，三角形允许但控制在 20% 以下（除三角扇/三角带）。
2. **无 N-gon**（>4 边面禁止导出）。
3. **无重叠面/共面面**（防 z-fighting，见质量清单）。
4. **法线朝外**，无反转面。
5. **疏密有度**：近景角色/主角面数上限高，远景植被用低面替代；禁止整体均匀高模。
6. **对称基础 + 非对称修饰**：动物身体对称建模，斑纹/姿态用非对称细节。

## 7. 品类视觉语言（Character / Environment / UI / Creature）

### 7.1 角色（农场主）

- 大头 Q 版、帽子（草帽/棒球帽可换）、背带裤 + 衬衫；暖色调为主。
- 表情五官用色块/简单几何（眼 = 深墨绿圆点或椭圆，腮红 = 淡粉圆斑 `#F4A9A9` 可选）。
- 动画需求见第 8 节；骨骼见资产规格文档。

### 7.2 动物（牛/羊/鸡/鸭/猪等）

- 圆身体 + 大脑袋 + 短腿；配色从第 2.3 节皮毛区间采样。
- 每物种一个「可识别剪影」：牛 = 角+铃铛、羊 = 蓬松卷毛、鸡 = 红冠+尖喙。

### 7.3 环境

- **地形**：草地用大面积纯色 + 顶点色色斑（深浅绿斑驳），可配少量低模草片点缀（instancing）。
- **水体**：半透明蓝色平面 + 轻微动画法线（或用 Standard 低粗糙度），不追求写实反射。
- **天空**：纯色 + 低模云朵（instancing），不建议 HDR 环境贴图（风格不符 + 体积大）。

### 7.4 UI

- 面板底：奶油白 `#F5EFE0` + 圆角（半径 8–12px）+ 细描边（深墨绿 2px）。
- 按钮：鸡蛋黄底 + 深墨绿文字；hover 提亮，按下压暗。
- 图标：同风格低模/扁平卡通，禁用写实照片图标。
- 字体：圆体（如 得意黑/圆体类），禁用衬线体。
- UI 的完整交互规范由文策渊产出，本文档只约束视觉。

## 8. 动画原则（Animation）

1. **夸张弹性（Squash & Stretch）**：落地/起跳/受击必须有挤压拉伸，幅度 10–20%。
2. **预备动作（Anticipation）**：攻击、跳跃、进食前 2–4 帧反向预备。
3. **次运动（Secondary Motion）**：尾巴、鸡冠、铃铛等附属物滞后摆动。
4. **节奏**：走跑循环 8–16 帧循环；呼吸/待机循环 24–48 帧，幅度小。
5. **帧率**：动画数据烘焙 30fps；视觉可做「2 帧一顿」的卡通步态（stepped），但数据仍 30fps。
6. **循环无缝**：所有循环动画首尾帧一致（可平滑 loop）。
7. **优先级**：位移动画由程序驱动（Rapier 移动），骨骼动画只负责姿态——**动画不写绝对位移**，位移交给物理/代码。

## 9. 预算与命名（Budget & Naming）

### 9.1 场景性能预算（Web 目标，移动端为中配基准）

| 指标 | 预算（单屏） |
| --- | --- |
| 三角面（tris） | ≤ 200k |
| Draw Call | ≤ 150（开启合批/instancing） |
| 同屏网格实例数 | ≤ 300（含 instancing 草/树） |
| 骨骼动画角色同屏 | ≤ 15 |
| 纹理 VRAM | ≤ 128 MB |
| 阴影贴图 | 1024×1024 × 1 主光 |

> 以上为**建议预算**，最终以程基岩的渲染管线实测为准；本预算与资产规格文档的面数分级联动。

### 9.2 命名规范（文件/资产）

统一 `snake_case`，格式：`<类型前缀>_<名称>_<变体/序号>[_lod<层级>]`
前缀与资产清单 ID 体系（design/asset-manifest.md）一一对齐：`ANI→animal_`、`PLA→plant_`、`FIS→fish_`、`BLD→building_`、`ITM→prop_`、`ENV→terrain_`。
GLB 文件名前缀为文件系统命名；manifest 内 assetId 采用 `<category>_<name>` 形式（category 枚举见工程管线）。

| 类型前缀 | 清单 ID | 含义 | 示例 |
| --- | --- | --- | --- |
| `char_` | —（角色单独命名） | 角色 | `char_farmer_01.glb` |
| `animal_` | ANI-xxx | 动物 | `animal_cow_brown_lod0.glb` |
| `plant_` | PLA-xxx | 植物 | `plant_tree_oak_01.glb` |
| `fish_` | FIS-xxx | 鱼类 | `fish_salmon_01.glb` |
| `building_` | BLD-xxx | 建筑 | `building_barn_01.glb` |
| `prop_` | ITM-xxx | 道具 | `prop_bucket_blue.glb` |
| `terrain_` | ENV-xxx | 环境/地形 | `terrain_ground_grass.glb` |
| `col_` | —（GLB 内部节点） | 碰撞体节点 | `col_trunk` |

- 纹理：`<资产名>_albedo.png` / `_normal.png` / `_or.png`。
- 禁止空格、中文文件名、大写（目录名除外）；禁止版本号后缀（用 git 管理版本）。

### 9.3 文件格式

- 网格资产：**GLB（glTF Binary）** 统一，目标 Three.js `GLTFLoader`。
- 纹理：源 `.png`，运行期 `WebP`（或 KTX2 待定）。
- 动画：内嵌于 GLB 的骨骼动画。
- 场景：不导出场景文件，场景由代码组装（Three.js 场景图）。
